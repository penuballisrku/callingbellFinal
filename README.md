# Calling Bell

Real-time local business discovery, lead generation and booking platform. **Discover. Connect. Book. Grow.**

```
SQL Server 2022+  →  .NET 8 Web API (Clean Architecture, CQRS/MediatR, EF Core, SignalR)  →  React 19 + TypeScript (Vite)
```

| Folder | Contents |
|---|---|
| `database/scripts` | Idempotent schema extension + realistic seed data (`00`–`13`, `RunAll.sql`) |
| `backend` | `CallingBell.Domain` · `.Application` (CQRS handlers, validators) · `.Infrastructure` (EF Core, Identity, JWT) · `.Api` (controllers, hubs) |
| `web` | Customer site, business portal (`/business`) and admin console (`/admin`) in one Vite app |

## 1. Database

The scripts extend the existing `CallingBell` database (originally created by EF migrations `InitialCreate` and `AddSubCategoriesAndMedia`). Existing rows are preserved. Every script is safe to run repeatedly.

```powershell
cd database/scripts
sqlcmd -S .\SQLEXPRESS -E -C -d CallingBell -i RunAll.sql
```

In SSMS or Azure Data Studio, open `RunAll.sql` with **SQLCMD mode** enabled. Execution order is `00, 01, 02, 03, 08, 04, 05, 06, 07, 09, 10, 11, 12, 13`. `08_Users` runs before the business scripts because reviews, leads and bookings reference customers. Business-owner accounts are created in `04_Businesses`.

What the seed creates:
- **Catalogue and reach:** 10 live cities and 1 launching soon, 52 localities with real pincodes, and 11 categories with 43 sub-categories.
- **Businesses:** 92 businesses (active, pending, suspended and inactive) with 382 services, working hours and gallery images.
- **Activity:** about 1,460 reviews, 3,100 leads and 3,500 bookings spread over 12 months.
- **Monetisation:** 61 ad campaigns, 5 subscription plans with full billing history, and about 1,500 invoices.
- **Analytics:** 180 days of business analytics and 365 days of platform DAU/MAU.

**Images** are SVG artwork generated by the scripts and stored in `dbo.Media`. Entities reference them as `/api/media/{id}` through `ImageUrl` / `ThumbnailUrl` / `MobileImageUrl` / `DesktopImageUrl` / `AltText` / `IsPrimary`. The UI falls back to an initials tile if an image is ever missing.

## 2. API

```powershell
cd backend
dotnet run --project src/CallingBell.Api --launch-profile http     # http://localhost:5080, Swagger at /swagger
```

- **Configuration:** `ConnectionStrings:CallingBell`, `Jwt:*` and `Cors:AllowedOrigins` live in `appsettings.json`. A development-only JWT key is in `appsettings.Development.json`. For any shared or production environment, supply `Jwt__Key` (≥ 32 bytes) through user-secrets or an environment variable.
- **Response envelope:** every endpoint returns `{ success, message, data, pagination }`. Validation errors also include `errors: { field: [messages] }`.
- **Security:** JWT access tokens plus rotating refresh tokens with reuse detection, RBAC roles, permission policies (`permission` claims on roles), per-IP rate limiting, an audit trail (`AuditLogs`) and soft deletes.
- **Real-time:** `/hubs/presence` broadcasts live availability changes, and `/hubs/notifications` pushes per-user lead, booking and listing alerts.

## 3. Web

```powershell
cd web

```

Requires Node 20.19+ (React Router is pinned to v7 for Node 20 support).

## Google sign-in

"Continue with Google" appears on the sign-in and register pages once a Google OAuth Client ID is configured. It stays hidden until then.

1. In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), create an **OAuth client ID** of type **Web application**.
2. Under **Authorized JavaScript origins**, add `http://localhost:5173` and your production site origin. No redirect URI is needed, because the button uses popup mode.
3. Give the Client ID to the API by setting `Authentication:Google:ClientId`, either in `appsettings.json` or with:
   ```powershell
   cd backend/src/CallingBell.Api
   dotnet user-secrets init
   dotnet user-secrets set "Authentication:Google:ClientId" "<id>.apps.googleusercontent.com"
   ```
   It is a public identifier, not a secret, and the web app reads it from `GET /api/auth/providers`.

Flow:
- **Verification:** the browser receives a Google ID token. `POST /api/auth/google` verifies its signature, expiry, issuer and audience (your Client ID), and requires a verified email.
- **Account handling:**
  - First-time users get an account; the register page's account-type toggle decides between Customer and Business owner.
  - Existing accounts with the same email are linked through `AspNetUserLogins`.
  - Deactivated or locked accounts are refused.
- **Session:** the response is the normal Calling Bell access token and refresh token.
